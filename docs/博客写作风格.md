# 舟遥的博客：技术文章写作风格

适用范围：深度学习、Transformer、loop transformer 和论文阅读系列。依据《深度学习引入》《自注意力机制》《transformer》《universal transformer》及作者对这四篇文章的修改要求整理。

目标：轻松、简单、易懂，但保留技术内容。读者读完不仅知道“这个方法大概有什么用”，还应该能顺着公式说清输入是什么、每一步算什么、参数如何学习、结果怎样得到。

## 1. 和读者一起把问题推出来

先接上上一节，再提出一个具体的新问题。比如从“输入一个向量”走到“输入一排向量”，从“固定层数”走到“同一套参数循环多次”。不要开头堆论文贡献、术语和背景综述。

一小段只推进一个问题：已有方法怎么做 → 在当前场景下哪里不方便 → 引入什么变化 → 怎样计算。让后一个式子解决前一句提出的问题。

可以自然使用“我们先看”“假设”“那接下来”“这里还有一个问题”“比如”等连接词，但不要每段都写成问答，也不要反复使用同一句过渡。

## 2. 用具体动作代替抽象评价

保留“一排向量”“拼起来”“再乘一个矩阵”“把上一轮的输出作为下一轮输入”这样的表达。先说发生了什么，再给术语；英文术语首次出现时配中文解释，后面可以直接用缩写。

语气可以有一点口语感，偶尔加“（笑）”，但不强行玩梗，不堆“神奇”“革命性”“颠覆”等评价。不要为了模仿而照搬旧文的笔误、重复词或不够准确的说法。

例：可以写“把这两个向量拼起来，长度就从 d 变成了 2d；再乘一个矩阵，把它压回 d 维”。不必写成“通过融合多源表征实现统一潜在空间中的高效信息交互”。

## 3. 简单的是讲法，不是内容

比喻最多帮助理解第一步，随后必须回到真实的变量和计算。例如用“进度条”解释 ACT 后，仍要写清停止分数、累计值、阈值、最后一轮的余量以及输出的合并方式。

不要把论文缩成“让模型多想一会儿，因此更聪明”。至少讲清核心更新式、训练目标、推理过程和一个有条件说明的实验结果。

不需要展开每项工程细节。与主线无关的实现参数、旁支方法、历史工作，可以略去或放到补充里。

## 4. 必要的地方要推公式

核心机制采用“动机 → 定义 → 公式 → 展开或小例子 → 解释结果”的顺序。不能只把论文的最终公式贴出来，再说“显然可得”。

适合推导的地方包括：标量如何变成向量或矩阵形式；拼接与线性投影如何展开；权重为什么要归一化；循环展开后深度如何计算；停止条件依据什么量；损失怎样作用到参数。

推导做到能帮助理解就停，不为显得专业加入与主线无关的长证明。两三步展开、一个可手算的小例子，往往比十行抽象符号更有效。

先写最终输出怎样由各部分组成，再解释为得到这个输出需要哪些约束。例如先写加权输出，才能解释为什么权重要凑到 1。

自己构造的教学例子要说明“用一个简单例子看”；不要把示意推导说成论文模型的实际更新式，也不要把直觉当作收敛证明。

## 5. 符号必须当场交代

每个新符号出现时，说明它是标量、向量还是矩阵，来自输入、网络计算、可学习参数还是额外维护的统计量。

涉及循环时，明确下标和上标分别表示 token 位置、网络层还是循环轮次。延续前文“每个 token 是一列”的约定；若改用其他方向，先说明。

重点区分容易混淆的量：本轮输入与本轮输出、固定输入表示与不断更新的状态、预测头分数与实际权重、隐藏向量与词表上的概率分布。两个符号表示同一个量时直接说明，没必要换名。

公式中的矩阵维度要匹配；softmax 沿哪一个维度计算，需要能从文字或下标中看出来。

## 6. 面对读者，不把修改说明写进文章

正文是完整的讲解，不是对作者的批改记录。不要出现“你这里应该”“为了纠正前面的说法”“不能仅凭某句话就断定”等编辑口吻。

要修正一个概念，就把这一段写成自然、正确的解释。前文已经讲过的问题，用一句话衔接即可，不要重新辩论。例如只需说“上面讨论的都是输入一个向量的情况”。

## 7. 主线与补充分开

主体保留当前问题需要的最短解释。更完整的定义、适用条件、原论文与代码的差别，放在 Markdown 引用块中，并用“补充：……”开头。

引用块是补充，不是关键步骤的藏身处。读者不读补充，也应能跟上主线。不同来源的公式不一致时，明确分别是什么版本，不能把不同算法混写成一个。

## 8. 论文结论要有边界

先阅读指定原论文，优先用作者代码和模型说明核对实现。固定论文版本，避免把不同版本的表格数字拼在一起。

区分参数量、前向计算量、训练计算量、显存和实际速度。共享参数不代表重复计算免费；相同训练 token 数不代表相同训练 FLOPs。

介绍实验时写明任务、指标、循环次数、训练规模，以及必要的提示词或评测设置。准确率从 30% 到 40% 是提高 10 个百分点，不是提高 10%。不把不同评测条件下的数字直接相减。

“论文观察到”“可以这样理解”“这里构造的例子”要分清。不要把有限实验写成普遍保证，也不要把“没有专门监督每个潜在推理步骤”写成“没有用过数学或推理数据”。

## 9. 排版约定

主章节用三级标题（###），局部小标题可用四级标题（####）；目前网站目录不列出四级标题。标题写具体内容，不堆抽象口号。

短段落为主，关键判断适量加粗。对照信息用表格，推导用独立公式。长公式用 aligned 等环境合理分行；展示公式的两端 $$ 各占一行，并留空行。

图片只在帮助说明结构时加入，控制显示尺寸，不默认增加图注；不要依赖一张没有文字解释的图片承载全部计算。避免连续空行或大量 br 撑出空白。

原论文链接放在对应结论附近，文末可以列少量主要参考资料。读者正文里不出现“已连接实时更新”等网站实现提示。

## 10. 可复用的写作请求

按本文件的风格续写舟遥的技术博客。先阅读系列前文和指定原论文，用具体问题承接上一节，以轻松、简单、直白的中文讲解。先说明动机，再定义符号和计算步骤，在核心机制处给出必要的公式展开或可手算例子；不要过度科普化，也不要堆砌术语。区分论文原式、自己的教学例子和官方实现。正文面向读者，补充细节用引用块。实验结果注明来源与条件，核对数据和公式渲染。保留作者指定的标题、分类及修改范围。

## 发布前自查

- 读者能否回答“输入是什么、经过哪些计算、输出是什么”？
- 核心方法是否只有比喻，缺少计算？是否只有公式，缺少动机和符号解释？
- 变量有没有混用，矩阵维度、轮次和位置是否清楚？
- 有没有把编辑建议或对作者的说教留在正文里？
- 论文版本、数字、指标和比较条件是否一致？
- 是否检查了编辑器预览或阅读页，确认公式、表格、链接和图片可用？
